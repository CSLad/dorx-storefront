# DORX — сайт бренда

Витрина бренда DORX: каталог товаров, карточки с фотографиями и характеристиками,
корзина с отправкой заказа в WhatsApp и закрытая паролем панель управления,
через которую владелец сам наполняет сайт.

Небольшое приложение на Node: всё содержимое сайта — три JSON-файла, а картинки
лежат на диске, который переживает перевыкладку.

## Что умеет

**Публичная часть**

- Главная: герой с фирменной анимацией, бегущая строка, шесть категорий,
  блок акций, сравнение моделей, цифры, гарантии, обещания бренда,
  «Впишется ли» — габариты рядом с человеком ростом 170 см.
- Каталог: фильтр по категориям, поиск, счётчик найденного.
- Карточка товара: галерея с миниатюрами, цена и платёж по рассрочке,
  описание, таблица характеристик, кнопки «В корзину» и «Видео».
- Корзина: живёт в браузере покупателя, считает сумму и скидку по промокоду,
  оформление уходит готовым сообщением в WhatsApp.
- Страницы гарантии, условий и конфиденциальности, аккуратная страница 404.

**Панель управления — `/admin/`**

- Товары: добавление, правка, удаление; загрузка фотографий перетаскиванием
  или по ссылке, выбор главного снимка и порядка; характеристики парами.
- Акции: баннеры для главной и промокоды для корзины.
- Настройки: телефон, WhatsApp, Instagram и тексты на главной.
- Демонстрационные товары: шесть примеров одной кнопкой, чтобы посмотреть
  на наполненный сайт, и такая же кнопка, чтобы их убрать.

## Данные

Три файла в `DATA_DIR` — их же отдаёт сайт и правит панель:

| Файл | Что внутри |
| --- | --- |
| `products.json` | список товаров |
| `promos.json` | баннеры акций и промокоды |
| `site-config.json` | контакты и тексты |

Загруженные картинки складываются в `DATA_DIR/images/` и отдаются по адресу `/images/…`.
При первом запуске файлы берутся из папки `seed/`.

### Поля товара

```
id                 короткий адрес, создаётся из названия
name               название
sub                подзаголовок, тип товара
category           seating | mirrors | workspace | appliances | bath | home
warranty           например «12 месяцев»
hit, isNew         значки на карточке
price              цена в тенге
priceInstallment   платёж в месяц; если пусто — цена ÷ 24
youtubeUrl         видео
description        текст
images             список адресов, первый — главный
specs              характеристики парами «свойство: значение»
```

## Запуск на своём компьютере

```bash
npm install
cp .env.example .env   # впишите свой пароль
npm run dev
```

Сайт откроется на `http://localhost:3000`, панель — на `/admin/`.

Самопроверка, которая поднимает сервер и проходит по всем адресам:

```bash
node server/smoke.js
```

## Переменные окружения

| Имя | Зачем |
| --- | --- |
| `ADMIN_PASSWORD` | пароль от панели управления, обязательно задать |
| `SESSION_SECRET` | длинная случайная строка для подписи сессии |
| `DATA_DIR` | где лежат данные и картинки; на Railway — папка тома |
| `PORT` | порт; Railway подставляет свой |
| `CANONICAL_HOST` | главный адрес сайта, например `dorx.kz`. Заходы на любой другой адрес — на поддомен Railway или на `www` — навсегда уводятся сюда, чтобы поисковик не считал их разными сайтами. Пустое значение выключает переезд. Включать **только после** того, как домен заработал: иначе сайт будет уводить на мёртвый адрес |

## Где всё живёт

| Что | Где |
| --- | --- |
| Сайт | https://dorx.kz |
| Панель управления | тот же адрес и `/admin/` |

Пароль от панели задаётся переменной окружения и в репозитории не хранится.
Без него сервер не запустится.

## Выкладка на Railway

Сервис удобно привязать к ветке `main`: тогда каждая отправка в GitHub
выкладывается сама. Чтобы поднять копию с нуля:

1. Подключить том (Volume) и примонтировать его в `/data`, а `DATA_DIR`
   поставить в `/data`. Без тома загруженные фотографии пропадут
   при следующей выкладке.
2. Задать `ADMIN_PASSWORD` и `SESSION_SECRET`.

Проверка живости — адрес `/healthz`.

### Домен

DNS домена стоит держать в **Cloudflare** — и это принципиально. Railway
выдаёт только CNAME, а CNAME нельзя поставить на голый домен рядом с его
собственными служебными записями; многие регистраторы такую запись просто
отклоняют. Cloudflare «расплющивает» CNAME на голом домене и отвечает
обычным адресом, поэтому `dorx.kz` работает без `www`.

Записи в Cloudflare (все **DNS only**, серое облако — иначе Railway не
подтвердит владение и не выпустит сертификат):

| Тип | Имя | Значение |
| --- | --- | --- |
| CNAME | `@` | адрес, который выдал `railway domain` |
| CNAME | `www` | адрес, который выдал `railway domain` |
| TXT | `_railway-verify` | ключ из `railway domain` |
| TXT | `_railway-verify.www` | ключ из `railway domain` |


## Что стоит сделать перед запуском

1. Задать надёжный пароль от панели в переменной `ADMIN_PASSWORD`.
2. В «Настройках» вписать настоящий телефон и номер WhatsApp — сейчас там
   заглушки, а именно на этот номер уходит заказ из корзины.
3. Убрать демонстрационные товары кнопкой в разделе «Товары» и завести свои.
4. Показать юристу страницы «Условия» и «Конфиденциальность»:
   тексты написаны понятным языком, но это не юридическая экспертиза.

## Безопасность

- Пароль в панель не хранится на диске, сравнивается за постоянное время.
- Сессия — подписанная кука на 12 часов, недоступная скриптам страницы.
- Пять неверных попыток подряд с одного адреса — пауза десять минут.
- Загружать можно только JPEG, PNG и WebP не тяжелее 8 МБ.
- Записывать данные может только вошедший; читать их может кто угодно,
  потому что это и есть содержимое сайта.


## Карточки товаров

`tools/cards/` рисует карточки в фирменном стиле DORX: заголовок заглавными,
выносные линии с размерами, три плашки, знак «.DORX» с квадратной точкой.
Фон выбирается **по цвету товара** — тёмный товар на светлый фон, светлый
на тёмный.

```bash
python tools/cards/fonts.py      # один раз: скачать шрифты
python tools/cards/make_cards.py # нарисовать по card_plan.json
```

`card_plan.example.json` показывает формат: для каждого товара нужны чистое
фото на белом, заголовок, три плашки и, если есть, размеры.

⚠ Исходное фото должно быть **чистой студийной съёмкой**. Картинка, на
которой уже напечатан чужой знак или текст, не подойдёт: скрипт вырезает
белый фон и перенесёт на карточку всё остальное вместе с надписями.


## Управление из чата (MCP)

`mcp/server.js` — сервер MCP: позволяет вести каталог прямо из разговора,
не открывая браузер. Он ходит в тот же API, что и панель, поэтому панель
и чат никогда не разойдутся.

Инструменты: `list_products`, `get_product`, `add_product`, `update_product`,
`delete_product`, `upload_image`, `get_settings`, `update_settings`,
`site_status`.

Подключение уже описано в `.mcp.json` — достаточно открыть эту папку
в Claude Code и разрешить сервер. Пароль сервер берёт из `mcp/password.txt`
(файл в .gitignore) либо из переменной `DORX_ADMIN_PASSWORD`.

Адрес сайта задаётся в `.mcp.json` через `DORX_SITE_URL`. Держите там
**главный** адрес: если указать запасной, запросы на запись упрутся
в постоянную переадресацию.

```bash
node mcp/server.js   # проверить, что сервер запускается
```
